# Contributing to KINEX.js

Thank you for your interest in contributing to KINEX.js.

KINEX.js is an open-source JavaScript library focused on reusable UI components, animations and interactive experiences for modern web development.

We welcome contributions from developers, designers and the open-source community to help improve the library.

## Ways to Contribute

There are several ways to contribute to KINEX.js:

- Develop new UI components and interactive effects.
- Improve existing components and implementations.
- Fix bugs and resolve compatibility issues.
- Improve performance and code efficiency.
- Enhance accessibility and usability.
- Improve documentation and usage examples.
- Suggest new features and improvements.
- Report bugs and technical issues.

## Before You Start

Before making a contribution:

1. Explore the existing repository and its structure.
2. Check existing issues and pull requests.
3. Avoid duplicating work already in progress.
4. For major changes or new features, open an issue or discussion before implementation.

## Development Guidelines

All contributions should follow the general development principles of KINEX.js.

### Code Quality
- Write clean, readable and maintainable JavaScript.
- Follow the existing naming conventions and project structure.
- Avoid unnecessary complexity and redundant code.
- Keep implementations modular and reusable.

### Performance
- Prefer lightweight implementations.
- Avoid unnecessary external dependencies.
- Minimize unnecessary DOM operations.
- Ensure animations and interactions perform efficiently.

### Compatibility
- Prefer standard HTML, CSS and JavaScript APIs.
- Consider compatibility with modern browsers.
- Document browser requirements and external dependencies.
- Avoid introducing breaking changes without proper consideration.

### Component Development
New components should:

- Have a clear and specific purpose.
- Follow the existing component organization.
- Include all required implementation files.
- Avoid unintended interference with existing website styles.
- Provide clear usage and customization instructions.
- Include dependency information where applicable.

## Contribution Workflow

### 1. Fork the Repository

Create a fork of the KINEX.js repository under your GitHub account.

### 2. Clone Your Fork

```bash
git clone https://github.com/KINEX-js/kinex.js.git
```

### 3. Create a Branch

Use a descriptive branch name.

```bash
git checkout -b feature/component-name
```

Suggested branch prefixes:

- `feature/` — New features or components.
- `fix/` — Bug fixes.
- `docs/` — Documentation improvements.
- `refactor/` — Code restructuring.
- `test/` — Testing improvements.

### 4. Make Your Changes

Implement your changes while following the project's development guidelines.

Keep commits focused and use descriptive commit messages.

### 5. Test Your Changes

Before submitting:

- Verify that the component works as expected.
- Check for JavaScript errors.
- Test relevant browser compatibility.
- Ensure existing components remain unaffected.
- Verify CDN loading requirements where applicable.

### 6. Submit a Pull Request

Push your branch to your fork and open a Pull Request against the main branch of the official repository.

Include:

- A clear title.
- A description of the changes.
- The reason for the contribution.
- Relevant screenshots or demonstrations.
- Testing details.
- Related issue references, if applicable.

## Pull Request Guidelines

- Keep changes focused and relevant.
- Avoid unrelated modifications.
- Provide clear descriptions.
- Ensure implementation and documentation remain consistent.
- Respond constructively to review feedback.

Pull requests may be reviewed, requested for modification, accepted or declined by project maintainers.

## Reporting Bugs

If you discover a bug, open a GitHub Issue and provide:

- A clear description of the problem.
- Steps to reproduce the issue.
- Expected behaviour.
- Actual behaviour.
- Browser and environment details.
- Relevant code examples or screenshots.

Avoid including private information, credentials or sensitive data in public issues.

## Feature Suggestions

Feature suggestions are welcome.

Before proposing a feature, explain:

- What the feature does.
- Why it would be useful.
- How it could improve the library.
- Any relevant implementation considerations.

## Community Standards

All contributors are expected to:

- Communicate respectfully.
- Welcome constructive feedback.
- Avoid harassment or discriminatory behaviour.
- Keep discussions relevant and professional.
- Respect the work and contributions of others.

## Licensing and Contributions

By submitting a contribution, you agree that your contribution may be distributed under the license applicable to the KINEX.js project.

You must have the necessary rights and permissions to submit any code, assets or other materials you contribute.

Do not submit copied, proprietary or improperly licensed material.

## Questions and Discussions

For questions, suggestions and project-related discussions, use the GitHub Issues and Discussions sections of the official repository.
